# 知音 · 设计规范

知音的第一版看起来像 AI 生成的，交互流程也差，于是从「听」出发重新设计。这份规范来自 2026 年 10 月对 X 上设计师帖子、设计工程师文章和音乐产品案例的调研，之后所有界面改动都按它检查。

## 1. 产品是一个播放器，不是一篇文章

- 打开后 1 秒内就能听：舞台上已经放好当前电台的第一首，按空格就开始播放。
- 主循环是 听 → 一键表态（喜欢 / 不要 / 下一首）→ 继续听，全程不需要阅读。
- 推荐理由只在「正在播放」的那首旁边出现一行，列表里不放。
- 慢的工作（每天的推荐、按描述找歌）都在后台跑，不显示进度日志，完成后用一条轻提示告诉你。推荐每天自动更新，不需要手动点「换一期」。
- 播放器的位置固定，永远不浮在内容上面。

## 2. 布局

- 桌面端三栏：电台 | 舞台（大封面 + 歌曲信息）| 接下来，一屏放下，页面不滚动。
- 窄屏把电台变成顶部横向滚动条；手机端单栏，舞台在上，队列在下，舞台滚出屏幕后底部出现迷你控制条。
- 「你的耳朵」页显示口味画像，播放器缩到右下角的 dock，音乐不中断。

## 3. 视觉

- 深色中性底 `#0b0b0c`。氛围色从当前封面里提取，限制饱和度和明度，用 `@property` 做 700ms 过渡。这是唯一的彩色来源。
- 字体只用系统字体：`-apple-system` / SF Pro + PingFang SC。不用衬线字体，不用斜体英文副标题，不用 Inter / Geist / Space Grotesk，也不用 Google Fonts。
- 字号阶梯 12 / 13 / 15 / 18 / 22 / 32；字重只用 400、500、600；大字号字距 −0.01em；时长和计数用 `tabular-nums`。
- 文字层级靠白色透明度区分：.92 / .62 / .42。
- 圆角：控件 6，行 8，封面 10，大封面 12；嵌套时内外圆角保持同心。
- 不用卡片，不用边框盒子，不用按分类配色的圆点，不用 pill 徽章，不用渐变按钮，不用发光效果，不用 emoji。分组靠留白和对齐。

## 4. 动效（数值参考 Emil Kowalski、Rauno Freiberg、Vercel 设计规范）

- 交互动画不超过 200ms，统一用 ease-out `cubic-bezier(.23,1,.32,1)`；氛围色和封面交叉淡化最多 700ms。
- 按下时缩放到 `scale(.97)`。缩放动画不从 0 开始，最小从 .9 开始。
- 键盘触发的动作不加动画，列表增删不加动画，菜单打开不加动画。
- 只动画 `transform`、`opacity`、`filter`，不写 `transition: all`。
- 遵守 `prefers-reduced-motion`。

## 5. 交互

- 乐观更新：喜欢和不要都立即生效，失败时回滚；「不要」会立即跳到下一首，并在底部提示条里提供撤销和「这位歌手也不要」。
- 键盘：空格 播放 / 暂停，N 下一首，P 上一首，L 喜欢，X 不要，1–9 切换电台，/ 输入想听什么，Esc 退出输入框。
- 点击目标在桌面端至少 24px，手机端至少 44px；手机端输入框字号不小于 16px。
- 加载态延迟 200ms 才出现，出现后至少停留 300ms。空态、加载态、错误态每个界面都要有。
- 队列快听完时，「再来几首」直接从备选里补，不用等待；「沿着这首继续」用这首歌的电台继续往下放。

## 6. 文案

- 写真实内容，不写口号：电台的副标题列出它里面真实的歌手。
- 能删掉 30% 的字就删掉。不加小标题上方的提示标签，不写「不是 X，是 Y」这种句式，不堆破折号。
- 推荐理由要像一个懂行的朋友说的话：先说这首歌听起来怎么样，再顺带一句是从哪首引过来的。

## 7. 播放器（v3）

目标是在日常听歌这件事上比 YouTube Music 和 Spotify 做得更好，不是功能堆得更多。

- 歌词三个来源并行查，取第一个有结果的：网易云（逐字时间轴、中文翻译、罗马音、作词作曲编曲）→ LRCLIB → YouTube Music 自带（LyricFind / Musixmatch）。匹配按 LDDC 的做法：时长差超过 4 秒直接排除，歌名和歌手各占一半分。
- 歌词宽屏放在封面旁边；舞台内容宽度小于 560px 时放在控制条下面，像 Spotify 手机版的歌词卡片。有逐字时间轴时逐字填色，前奏和间奏显示三个依次亮起的点。日文、韩文、英文歌如果没有现成翻译，后台用 AI 翻译补上（标注「AI 翻译」）。T 切换翻译，R 切换罗马音，点击任一行跳到那里，手动滚动后 3.5 秒回到跟随，[ 和 ] 按 0.25 秒微调这首歌的歌词时间并记住。
- 中文歌词用歌曲本身的写法：歌名、歌手、专辑是繁体就转繁体，连香港字形（説、着）和台湾字形（說、著）也跟着歌名走；作词作曲人名同样转换。
- 两个 YouTube 播放器交替使用：自然结束时等功率交叉淡化 3 秒，手动切歌时旧的一首 260ms 淡出，不会戛然而止。
- 系统层：Media Session（键盘媒体键、耳机按键、锁屏和控制中心），画中画迷你窗（M，封面、当前一句歌词和翻译、播放控制），沉浸模式（F，只剩封面、歌名和歌词，背景是模糊的封面，鼠标静止 2.6 秒后隐藏）。
- MV 换成录音室音轨：推荐里的官方 MV 如果在 YouTube Music 上有同一录音的音轨，就播放音轨（没有短剧情和长前奏，画面就是封面），MV 的 id 保留在 `mv` 字段里。
- 播放中的调整：跳过（播放不到 30 秒且不到一半）会把队列里听感相近的歌往后推，喜欢或听完会把备选里相近的歌提上来；队列头部有「更安静 / 更带劲 / 多些新歌手」三个纯文字开关。每次调整都会在电台副标题写一句为什么（比如「少放和〈X〉相近的」）。
- 键盘：空格 播放，N / P 切歌，L 喜欢，X 不要，G 歌词，F 沉浸，M 迷你窗，T 翻译，R 罗马音，[ ] 歌词时间，← → 快进快退 10 秒，1–9 电台，/ 输入。

## 8. 推荐怎么算

完整说明见 [how-it-works.md](how-it-works.md)，这里只记原则。

- 一首推荐好不好，只看一件事：你第一次听就想收藏。「听起来像你的歌」和「你没听过」都排在它后面。
- 找歌靠 YouTube Music 的听歌图谱：种子歌的电台和相关歌曲、相似歌手、核心歌手的新歌，再加上已经包含你至少两首喜欢的公开歌单。每条线约 600 首候选，排除已知和听过的，按图谱分取前 64 首。
- 声音只否决，不排序。MuQ-MuLan 对「会不会喜欢」的区分能力离线实测只有 AUC 0.55–0.61，用它排序会把轻柔的华语慢歌拉进爵士线。它负责三件事：避开你拒绝过的声音，播放中按跳过和喜欢实时调整队列，按文字描述找歌。
- Claude（Opus）当编辑：质量和质感优先，要写得好、唱得好、制作讲究的录音室原版；经典只要合适、你还没收藏，就欢迎；冷门本身不是理由。把握不到 0.7 的不出，宁缺毋滥。
- 只有听过或跳过的歌才算用掉。最近两期不重复，展示过但没播的过一阵还会回来。早期版本把 28 天内展示过的全部排除，每换一期就烧掉一批最好的候选，这是踩过的坑。

## 9. 产品形态

- 两种跑法，见 [self-hosting.md](self-hosting.md)。一是一台 Mac 自己用：`zhiyin service install` 用 launchd 常驻，每天 05:00 出新一期；Chrome 里可以安装成独立窗口的 App。二是一台小服务器给自己和几个朋友用：邀请链接进入，用 Google 登录读取各自的收藏，在知音里点喜欢会写回 YouTube Music；音频模型放在一台 Mac 上当 worker，服务器只发需求、收向量。
- 播放走 YouTube 官方嵌入播放器：完整曲库、合法播放，代价是播放器不能小于 200px，也拿不到音频流本身（所以不能做 EQ 或真正的无缝拼接，交叉淡化是用两个播放器的音量做的）。
- Claude 调用走 Claude Code 的 `claude -p`，用自己的订阅或 API key。数据都在自己的机器上，哪些内容会发给第三方见 [privacy.md](privacy.md)。

## 10. 发布前的 AI 感自查

- [ ] 有没有衬线标题加斜体英文、米色底、赤陶色强调色？
- [ ] 有没有按分类配色的圆点或徽章，或「Live / New」pill？
- [ ] 列表每一行下面是不是都挂着一句差不多长的说明？
- [ ] 有没有卡片、嵌套卡片、整齐划一的卡片网格、左侧色条？
- [ ] 是不是所有元素都用同一个上浮淡入动画、弹跳缓动或装饰性脉冲？
- [ ] 所有元素的圆角和内边距是不是都一样？
- [ ] 有没有口号式文案，或冗余的解释文字？
- [ ] 有没有 emoji 图标、渐变或发光？
- [ ] 空态、加载态、错误态是否都有？
- [ ] 有没有会挡住操作的进度日志或 spinner，有没有浮在内容上面的媒体？
- [ ] 每个元素去掉后，你会不会注意到它不见了？

## 11. 标识

「音」字的第一笔是一个点。标识把这一点换成琥珀色（`#E9A55B`）的圆，其余笔画保持字体原样：知音每天给你的，就是那一点，一首刚好的歌。

- 字形来自 Noto Sans CJK SC Light（SIL OFL 1.1），用同色描边加粗到接近 Medium；圆点悬在横画上方，不和笔画相连。
- 图标只用「音」，字标用「知音」，两者不并排出现。小尺寸（顶栏、favicon）把圆点放大，保证看得见。
- 琥珀色只用在这一个点和流程图的终点上，界面里的颜色仍然只来自封面。
- 文件在 `docs/brand/`。
